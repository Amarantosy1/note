## 项目介绍
因为我自己一直在使用Apple日历，攒下了很多的数据，我就在想着，能不能让这些数据产生一些价值，比如看清楚自己的时间到底去哪里了，指导之后的时间安排，就产生了这个项目的初步构建。
第一版我是想单纯做一个时间统计，就像屏幕使用时长那样，根据不同日历分类时间到底去哪了。

![[Pasted image 20260403222257.png]]

在使用coding完成项目的时候，我突然灵机一动，既然我能够使用AI帮我写这个项目，那为啥不能让AI帮我复盘我的时间呢，我的想法是，接入AI的API，然后能让它读取我的日程，对我在那个日程里干了什么发出提问，根据对话生成一份总结，这份总结包括AI发现你的时间规划大概是什么样子的，以及对后续的改进建议。

## 快速开始
1. 到GitHub仓库里下载release：https://github.com/Amarantosy1/iTime
2. 打开dmg文件，把app拖入application里
3. 在终端输入`xattr -dr com.apple.quarantine /Applications/iTime.app`，然后再打开app（因为没💰去买Apple的开发者会员。。
4. 在设置里配置API

## 复盘总结（with Claude

---

**iTime 开发复盘**

**最难的一关：AI 复盘功能的设计**

最初只想让 AI 分析日历数据，但意识到纯分析报告是空洞的——缺少"我"的主观感受。转折点发生在某天晚上准备写日记时，发现如果能通过和 AI 对话来复盘一天，日历数据和主观感受可以互相补充，日记也不需要再记流水账。这个洞察是从自己真实碰壁的场景里长出来的，不是凭空设计的。

**意外顺利的地方：Liquid Glass 效果**

WeekTask 时硬刚，卡了很久。iTime 时改用"胶水编程"——先找 GitHub 上实现好的参照项目，再让 AI 照着做，不重复造轮子。省掉的不只是时间，是把精力留给真正属于 iTime 的决策。

**git 管理的进化**

WeekTask 时没做好 git 管理，乱成一锅粥。iTime 时关掉了所有 agent 的 git 权限，高危操作需要先向自己提问，大改动前让 AI 做 worktree 隔离，验证完再合并回 main。本质是对 AI 的信任模型从"默认信任"变成了"默认不信任，验证后合并"。这套流程是踩坑自己摸索出来的，也是第一次真正用上 git。

**最大的认知变化**

AI 编程不能代替一切，自己一定要懂编程才能用好 AI。AI 能加速执行，但判断方案对不对、架构合不合理，需要自己有足够的基础才能接得住。

**下一步要补的短板**

架构设计和抽象设计。iTime 的分层结构是 AI 建议的，下一步要能用自己的话解释清楚每一层为什么这么划——说不清楚的地方，就是理解还没到位的地方。
